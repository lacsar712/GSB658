# 社区AI打卡与积分管理系统 - 需求规格说明书

## 1. 项目概述
本项目旨在开发一款社区管理的综合性应用系统，主要包含居民打卡、违规举报、积分商城以及AI智能问答等功能。系统分为前端居民侧、后端管理员侧以及跨模块的通用功能，旨在提升社区的智能化管理水平和居民参与的积极性。

## 2. 系统功能需求

### 2.1 居民端功能
1. **身份认证**：支持使用手机号和验证码进行注册与登录。
2. **社区绑定**：用户可选择并绑定所在的社区，以便于后续的精细化运营与管理。
3. **每日答题打卡**：系统提供每日答题活动，用户通过连续打卡和答对题目获得相应的积分。
4. **违规举报**：支持用户拍摄或上传违规照片，并结合高德地图 API 记录当前定位信息进行举报。
5. **积分商城**：用户可以使用获得的积分浏览商品分类、选择商品并完成兑换。
6. **AI智能问答**：提供针对社区日常事务、物业政策等内容的自然语言交互和多轮对话答疑服务。

### 2.2 管理员端功能
1. **数据可视化看板**：利用 ECharts 进行多维度数据展示，如用户活跃度、打卡统计、举报处理率等。
2. **居民管理**：审核新用户注册信息，处理用户反馈和账号状态（如启用/禁用）。删除相关操作必须提供优雅的 UI 设计二次确认提示（弹窗/Toast）。
3. **虚拟设备管理**：通过高德地图标记社区内的虚拟或实体设备位置，方便资产盘点与维护。
4. **积分规则配置**：灵活设置签到、答题、举报等操作的积分奖惩规则。
5. **AI问答管理**：管理和维护百度UNIT API所使用的话术库和问答规则配置。

### 2.3 共享模块
1. **积分商城**：统一的商品分类管理、库存管理以及兑换状态流转同步。
2. **AI问答**：整合百度UNIT API，支持前后端的自然语言交互记录及多轮对话的上下文管理。

## 3. 技术栈与开发环境说明

### 3.1 前端技术栈
- **核心框架**：Vue 3
- **UI组件库**：Element Plus (需符合现代审美，注重微交互设计)
- **图表库**：ECharts 5.4

### 3.2 后端技术栈
- **核心框架**：Spring Boot 2.7.x
- **持久层/数据库**：MySQL 5.6 
- **缓存引擎**：Redis 2.4

### 3.3 第三方服务
- **地图服务**：高德地图 API（JS API 及其 Web 服务端应用）
- **AI智能服务**：百度 UNIT API

### 3.4 开发环境与准备工作
- **JDK版本**：JDK 21
- **Node.js版本**：Node.js 16.x
- **数据库及缓存**：安装 MySQL 5.6，Redis 2.4.5 服务
- **第三方权限申请**：申请高德地图 JS API 和百度 UNIT API 开发权限并获取相应的 Key/Secret
- **工具链**：推荐使用 IntelliJ IDEA 或 VS Code，数据库客户端建议使 Navicat 等
- **容器化支持**：后续各服务都必须全面拥抱 Dockerization，满足 100% 容器编排 (Docker All-in-One) 规范
