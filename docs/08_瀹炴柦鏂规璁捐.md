# 系统开发与模块实现 - 实施方案设计

## 用户审核与确认

本阶段将正式进入核心业务逻辑的前后端开发。为了保证开发质量并符合“Github高星级标准”，在进一步批量编写业务代码之前，请确认以下技术架构或实现细节：

> [!IMPORTANT]
> **请审阅以下实现方案细节，确认是否同意按照此架构启动双端的业务编码：**

1. **前后端分离工程结构**：
   - 根目录下区分为 `frontend` 和 `backend` 两个独立工程。
   - `backend` 使用 Maven 多模块或单体结构（当前设计为包含 controller, service, mapper 的单体架构）。
   - `frontend` 使用 Vite/Vue3 搭建。
2. **鉴权方案的落地**：
   采用 `JWT (JSON Web Token)` + Redis 组合实现，短信验证码将缓存在 Redis 中（5分钟有效期）。
3. **数据库与第三方集成**：
   数据库表结构（MySQL）采用您上一阶段审核过的 ER 图设计。
   百度 UNIT (AI 智能问答) 及高德 API 将通过 Spring Boot 的 `RestTemplate` / `WebClient` 进行 Server-to-Server 的中转调用，避免前端直接暴露 Secret Key。

## 第一阶段：后端基础架构实现 (Spring Boot)

### 1. 核心依赖注入与配置
- 引入 `spring-boot-starter-web`，`mybatis-plus-boot-starter`，`spring-boot-starter-data-redis`。
- 引入 工具类库 `fastjson2`、`jjwt` 以及 `hutool` 等加速开发。
- 配置文件 `application.yml` 设定 MySQL 与 Redis 的连接池信息及应用端口（后端默认为: 8080）。

### 2. 数据库表与ORM建立
使用 Mybatis Plus Generator 生成以下核心表对应的 `Entity` 和 `Mapper`：
- `User` (用户与积分余额)
- `QuizRecord` (答题流)
- `PointAccount` (积分详细账户流)
- `VirtualDevice` (虚拟设备表)
- `Product` (积分商城商品)
- `Report` (违规举报)

### 3. API开发规划
根据需求说明，后端将划分为以下几大 `Controller`：
- `AuthController`: 短信验证码获取、登录逻辑。
- `QuizController`: 拉取当天的答题任务、提交答案并计算积分。
- `PointController`: 积分商城商品拉取、分布式并发安全兑换(Redis + Lua 或 Redisson 锁)。
- `ReportController`: 接收带坐标的图文举报，入库并支持管理端查询处理。
- `AIChatController`: 接收居民提问文本，封装向百度 UNIT API 发送 REST 请求并返回数据。
- `AdminController`: 聚合数据看板指标，输出到 ECharts；更新用户和设备状态。

## 第二阶段：前端基础架构实现 (Vue 3)

### 1. 框架与UI组件库
- 初始化基于 `Vite` 的 `Vue 3` (组合式 API) 项目。
- 引入完整版 `Element Plus`。考虑到您的“极高美观度”要求，将结合 `TailwindCSS` 或自定义 `index.css` 重写部分基础组件的原生样式（如圆角、渐变悬浮、骨架屏加载过渡等）。
- 引入 `ECharts 5.4` 为管理台提供可视化图表支持。

### 2. 双端展现形式 (路由规划)
- **居民端**：倾向于类似 Mobile WebApp 或 H5 的布局规范，居中自适应容器，底部配备固定的 TabBar 切换（首页打卡、举报、积分商城、我的）。
- **管理端**：侧边栏 + 顶栏 的经典 B/S 布局（Dashboard 数据看板、用户管理、设备定位大屏）。

## 验证与测试建议

### 本地调试验证
- 后端：确保可以联通本地（或 Docker 提供）的 MySQL 与 Redis 成功启动。在控制台观察所有的 Mybatis SQl 输出和日志拦截情况。
- 前端：使用 `npm run dev` 启动，通过 Axios 请求走 Vite 代理到后端端口解决跨域，完成页面到数据库的全链路贯通。

### 测试用例
1. [并发性测试]：利用 JMeter 或 Apifox 测试积分兑换接口的并发，检验 Redis 预扣减是否发生超卖。
2. [正确性测试]：全流程走通一个完整的注册绑定 -> 连续答题获取积分 -> 提交举报 -> 获取高德解析 -> AI 提问会话过程。
