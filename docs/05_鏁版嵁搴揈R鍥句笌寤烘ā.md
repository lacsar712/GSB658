# 数据库 E-R 图与建模设计

## 1. 核心实体关系图 (E-R Diagram)

以下是系统核心实体的 ER 关系模型，清晰描述了用户、答题记录、积分、设备、商品和违规举报等实体之间的业务与关联关系。

```mermaid
erDiagram
    USER ||--o{ QUIZ_RECORD : "参与完成"
    USER ||--|| POINT_ACCOUNT : "唯一拥有"
    USER ||--o{ REPORT : "拍摄/提交"
    
    USER {
        bigint id PK "用户ID 主键"
        varchar phone "手机号"
        bigint community_id "社区ID"
        int point_balance "积分余额(冗余/预存)"
        datetime create_time "创建时间"
    }
    
    QUIZ_RECORD {
        bigint id PK
        bigint user_id FK "用户ID"
        bigint question_id "题目ID"
        varchar answer "用户提交答案"
        boolean is_correct "是否正确"
        int score_awarded "此次得分"
        datetime create_time "答题时间"
    }
    
    POINT_ACCOUNT {
        bigint id PK
        bigint user_id FK "用户ID"
        int total_points "累计获得积分"
        int today_points "当日获取积分"
        datetime update_time "更新时间"
    }
    
    VIRTUAL_DEVICE {
        bigint id PK
        varchar device_no "设备ID编号"
        decimal longitude "坐标：经度"
        decimal latitude "坐标：纬度"
        int status "状态(0正常/1预警/2满溢)"
        datetime update_time "最后同步与更新时间"
    }
    
    PRODUCT {
        bigint id PK "商品ID 主键"
        varchar name "商品名称"
        int category "分类(例如:生活用品/食品/服务)"
        int point_price "所需兑换积分价格"
        int stock "剩余库存余额"
        datetime create_time "创建时间"
    }
    
    REPORT {
        bigint id PK "举报记录聚合ID"
        bigint user_id FK "提交人用户ID"
        varchar photo_url "上传照片的存储路径"
        decimal longitude "上报经度"
        decimal latitude "上报纬度"
        varchar location_detail "高德解析之详细定位"
        int status "处理状态(如:待审核/已处理/已驳回)"
        datetime create_time "举报提交时间"
    }
```

## 2. 字段与存储策略说明

1. **用户表 (`user`)**：
   - 包含用户的登录凭证和状态。`point_balance` 是当前积分余额的核心字段，变更时必须结合事物或乐观锁以防并发问题影响数据一致性。

2. **答题记录表 (`quiz_record`)**：
   - 对于 `answer` 和 `is_correct` 进行留存以便追溯每日的打卡行为。

3. **积分账户表 (`point_account`)**：
   - 作为用户积分流水和宏观限制的汇总，利用 `today_points` 用于限制每日最多可获得积分的规则判断。

4. **虚拟设备表 (`virtual_device`)**：
   - `longitude` / `latitude` 应用 Decimal 或 Double 数据格式精准存储基于高德地图的经纬度，`status` 设计为枚举 Int 提升查询效率。

5. **商品表 (`product`)**：
   - 当商城发生并发兑换时，`stock` 将搭配 Redis 使用 Lua 脚本进行预扣减并落库保障一致性。

6. **举报记录表 (`report`)**：
   - 对于 `photo_url`，存储 OSS 地址或容器化服务的相对文件路径挂载；`status` 流转需配合相应的后端服务流完成闭环。
